Tema 01AI-Powered Coding

Generación de código y asistencia al desarrollo

El autocompletado ya es el caso más maduro: no solo sugiere la siguiente línea, propone la función completa, el test y la explicación. La pregunta dejó de ser si funciona y pasó a ser cuánto del resultado podemos verificar.

auth/session.ts IA
1import { db } from "./db";
2import { hash } from "./crypto";
3
4export async function login(email, password) {
5 const user = await db.users.find(email);
6 if (!user) return null;
7 const ok = await hash.check(password, user.hash);
8 return ok ? await db.sessions.create(user.id) : null;⇥ Tab
9}

La sugerencia llega completa; aceptarla con Tab es un acto de confianza, no una verificación.

Señal

Mide tiempo hasta el primer PR y tasa de retrabajo, no el porcentaje de código generado.

  • 01

    Del autocompletado al agente

    De sugerir una línea a ejecutar un plan de varios archivos con herramientas propias.

  • 02

    Contexto sobre parámetros

    El modelo rinde según lo que ve: repositorio, convenciones, historial y pruebas existentes.

  • 03

    Revisión como cuello de botella

    Generar es barato; leer, entender y aceptar sigue costando tiempo humano.

  • 04

    El riesgo se mueve

    Menos errores de sintaxis, más decisiones de diseño aceptadas sin discusión.

Tema 02AI in QA & Testing

Pruebas automatizadas y aseguramiento de la calidad

La IA escribe pruebas rápido, incluidas las que nadie pidió y las que siempre pasan. El valor está en cubrir el comportamiento correcto, no en inflar el número de casos.

Dónde ayuda de verdad

Unitariasalto
Integraciónmedio
E2Ebajo

La IA abarata escribirlas; no abarata mantenerlas.

Señal

Un test que nunca puede fallar no es cobertura: es ruido.

  • 01

    Casos a partir de requisitos

    Genera escenarios y datos límite desde historias de usuario, con revisión humana.

  • 02

    Pruebas que se adaptan

    Ante un cambio de interfaz, localiza selectores y reescribe pasos rotos.

  • 03

    Triaje de fallos

    Agrupa fallas por causa probable y descarta el ruido de inestabilidad.

  • 04

    El riesgo del falso verde

    Una prueba generada puede validar el error en lugar de detectarlo.

03

Tema 03Requirements & Project Management

Ingeniería de requisitos y gestión de proyectos

Escribir una especificación completa toma minutos; decidir qué vale la pena construir sigue tomando reuniones. La IA acelera el papeleo del alcance, no la responsabilidad sobre él.

Trazabilidad sin planillas

Requisito→ Test→ PR→ Despliegue

Si el enlace se rompe, el requisito deja de existir en la práctica.

Señal

La IA acelera la redacción del alcance. La decisión sobre el alcance sigue siendo del equipo.

  • 01

    De la entrevista al requisito

    Transcribe, resume y estructura hallazgos; el acuerdo con el cliente sigue siendo humano.

  • 02

    Detección de ambigüedad

    Señala requisitos contradictorios, incompletos o imposibles de verificar.

  • 03

    Estimación asistida

    Cruza alcance con historial real del equipo, no con promedios de la industria.

  • 04

    Trazabilidad automática

    Enlaza requisito, tarea, commit y despliegue sin planillas manuales.

Tema 04MLOps & Architecture

MLOps y arquitectura de software para sistemas de IA

Un modelo en un notebook no es un producto. MLOps es la disciplina que convierte ese experimento en un servicio observable, versionado y reemplazable.

El ciclo como sistema

01Datoslinaje y versión
02Modeloentrenamiento
03Servingcontrato y latencia
04Evaluaciónderiva y calidad

La evaluación alimenta la siguiente versión: por eso es parte del ciclo, no el final.

Señal

El ciclo de vida es el producto; el modelo es una pieza reemplazable.

  • 01

    Versionar datos y modelos

    El código es la parte fácil: sin linaje de datos no hay reproducibilidad.

  • 02

    Serving con contrato

    La inferencia es una API más: latencia, cuotas, errores y retrocompatibilidad.

  • 03

    Monitoreo de deriva

    El mundo cambia antes que el modelo; hay que detectarlo en producción.

  • 04

    Evaluación continua

    Las métricas offline no garantizan calidad online; ambas se miden y se comparan.

Tema 05Self-Healing Software

Depuración automatizada y sistemas autocurativos

Detectar, diagnosticar y corregir sin intervención humana es posible en un rango acotado. Fuera de ese rango, automatizar la corrección puede multiplicar el incidente.

Límites de la autonomía

Auto

Reiniciar, reintentar o revertir un despliegue con reglas explícitas y registro.

Humano

Cambios de configuración o de datos: se proponen, no se aplican solos.

Nunca

Mutaciones de esquema o de permisos sin aprobación nominal.

La autonomía se gana por tipo de acción, no por confianza general en el sistema.

Señal

Autocurar sin límites es apagar un incendio con gasolina.

  • 01

    Correlación de señales

    Cruza logs, trazas y métricas para ubicar la causa antes que el tablero de guardia.

  • 02

    Hipótesis y reproducción

    Propone una causa y arma el caso mínimo que la confirma o la descarta.

  • 03

    Remediación acotada

    Reiniciar, revertir o escalar según reglas explícitas, con registro de cada acción.

  • 04

    El límite es el diseño

    Cuanto más escribe el sistema en producción, más estricto debe ser el permiso.

CierreDiscusión

Tres criterios para no delegar a ciegas

  • 01

    Supervisión proporcional

    Cuanta más autonomía, más evidencia y revisión por muestra.

  • 02

    Evaluación propia

    Si no puedes medir el resultado, no puedes aceptarlo.

  • 03

    Propiedad del cambio

    Alguien con nombre y apellido responde por lo que se despliega.
